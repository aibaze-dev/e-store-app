# Meeting Prep

Public route: `/a/meeting-prep`. A category-first, six-step wizard in English. It helps someone prepare to participate in a meeting; the brainstorming scenario also supports facilitating a discussion.

## Templates and data

`templates.js` contains six scenarios, their questions, example answers, and fixed openings/closings. Add or revise wording there. The stages are situation, audience, outcome, main point, up to three supporting facts, and a specific ask. Outcome and main point are required. Optional blanks are omitted; a missing ask becomes “Can we agree on the next step?”.

`buildCard(form)` produces a separate snapshot, preserving user wording, including whitespace and line breaks. It returns `null` for missing required fields. `cardBlocks(card)` provides the display blocks, `cardText(card)` produces the copyable version, and `rehearsalPrompt(card)` uses the current card (including manual edits) to prepare instructions for a role-play in Claude. Nothing is inferred, translated, researched, or generated by AI.

All card blocks, supporting facts, audience, and goal can be edited directly. The screen, copied text, print sheet, practice view, and rehearsal prompt use the same card state. Returning to the wizard does not replace that card. Rebuilding an edited card, loading an example over existing work, or starting over requires confirmation.

No tool-specific backend calls, AI services, storage, tracking, or microphone access are used. Answers and edits exist in React state only and disappear on reload. This differs intentionally from the independently maintained Prompt Builder history. The application shell's existing auth provider remains unchanged; this public tool does not require a session.

## Practice and printing

`timer.js` implements a 60-second timer with idle, running, paused, and finished states. It stores an absolute deadline while running, so delayed callbacks or background tabs do not extend a session. Pausing snapshots the remaining duration; resuming excludes paused time. Reset returns to idle and requires another explicit start. Leaving practice discards that timer; opening practice again starts a fresh idle session.

Printing uses the browser's Print / Save PDF dialog. A dedicated, text-based print sheet renders from the current card, avoiding truncated textarea contents. Print CSS hides the interface and shows only the card. Browser-supplied page headers/footers remain controlled by the print dialog. Long cards may span multiple pages.

All styles are scoped to `.artifact-meeting-prep`, including print rules and the confirmation dialog root. Metadata and lazy component registration remain separate. There are no new dependencies or Convex schema changes.

## Checks

`test/meeting-prep.test.js` covers every scenario, required fields, optional omissions, preservation of supplied facts, independent snapshots, manual edits flowing into exports, rehearsal instructions, and deadline/pause/resume/expiry behavior. Run `pnpm test` and `pnpm build` before release. Browser checks should include copying and its manual fallback, keyboard navigation, examples, rebuild cancellation, printing edited text, timer controls, public direct access, mobile layouts, and CSS isolation. Production deployment is separate from local validation.
